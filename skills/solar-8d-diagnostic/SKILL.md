# 太陽光電案場 8D 異常診斷與標準化決策平台生成技能 (Solar 8D Diagnostic)

本技能提供標準化的作業指引，協助工程師與 AI Agent 將光電案場的**竣工圖紙、SCADA 遙測日誌、現場巡檢照片、微氣候環境數據**，轉化為嚴格符合 **8D (D0~D8) 問題解決方法論**的深度診斷分析，並自動編譯為風格統一、互動流暢、數據與照片完全可溯源的高階決策平台 (HTML)。

---

## 🎯 核心原則與雙軌規格 (Dual-Track Standard)

1. **原創視覺風格與專業色系 (Original Visual Identity)**：
   - 延續經典顧問級深海軍藍（Deep Navy `#0C3A63`）、工程主藍（`#1968AD`）、綠松石綠（`#1BB1BF`）、警告琥珀（`#E09A2B`）與告警珊瑚紅（`#D95F45`）。
   - 保持卡片化佈局、Noto Sans TC 與 JetBrains Mono 雙字體、固定頂部導航欄與響應式目錄 (Sticky TOC / Slide Deck Controls)。
2. **雙軌報告視角支援 (Internal O&M vs. Owner Delivery)**：
   - **內部維運版 (Internal O&M Version)**：聚焦於技術根因剖析、除草驗收缺陷檢討、承商責任界定、詳細電氣檢測流程 (IEC 62446-1) 與防再發作業規程。
   - **業主交付版 (Owner Delivery Version)**：著重於資產發電效益挽回、火載量消防安全、透明化客觀事實推論、財務 ROI 模型 (CAPEX/OPEX/回本期) 與投資人價值提升。
3. **標準 8D 結構與章節規範 (Strict 8D Structure)**：
   - **Cover 封面**：電廠案號、地籍坐標、裝置容量、資料期間、版本、發布日、核心精華一句話 (`lede`) 與基本參數網格 (`factgrid`)。
   - **摘要 (Summary)**：4 大核心指標卡片 (`.kpi`, `.kpi.bad`, `.kpi.warn`)、優先順序問題清單 (`P1~P4`) 與「最該帶走的一句話」。
   - **D0 立案與緊急反應**：接獲異常時間、事實判定 (`.stmt.fact`)、是否停機判定、火載量與直流電弧疊加風險。
   - **D1 小組與分工**：資料分析、現場執行、監控系統、業主窗口之人員與責任定義表。
   - **D2 問題描述 (量化)**：5W2H、平台登錄容量 vs 串接圖實際容量對帳表、以真實容量重算的 90 天單位發電量排名與短少 kWh。
   - **D3 暫時圍堵措施**：止血行動項目（含責任人、期限與嚴謹的「驗證門檻」）。
   - **D4 根本原因分析**：
     - 關鍵實證圖組 (`.ev-grid`, `EV-01` ~ `EV-04`)，附帶拍攝時間戳記與對應 D 步驟。
     - 實證與推論鏈 (`.stmt.fact`, `.stmt.inference`)。
     - 「已排除的假設表格 (`.excl`)」：明確列出排除逆變器削峰、電氣組串斷路、A組效能偏低、組件衰退等理由。
     - 延伸風險警告：旁路二極體長期導通、接線盒過熱與熱斑損壞。
   - **D5 永久對策選定**：選項比選表（改除草SOP、防草蓆/抑草工法、提高支架、除草劑等之投入、產出、限制與採用理由）。
   - **D6 執行與效果驗證**：行動項目與驗證門檻（如比值回到 $\ge 0.90$ 判定有效；$<0.80$ 啟動 IEC 62446-1 兆歐表與 IV 曲線電氣檢測）。
   - **D7 防止再發**：除草 SOP 修訂（割草背對模組/擋板、清運寫入驗收條件、生長季頻率）、驗收方式、自動告警規則與水平展開。
   - **D8 結案與歸檔**：結案條件（比值 $\ge 0.90$ 穩定 7 天、熱像無異常）、文件歸檔與月度後續追蹤。
   - **附錄B 原始資料來源**：來源檔案、期間、筆數與用途說明（確保所有數字可回溯重算）。
   - **附錄C 分析限制**：坦誠揭露本分析不能回答的事項（無組串細項數據、基準台潛在遮蔽等）。
   - **安全 作業安全警語**：動工前必讀（高壓直流無法完全斷電、嚴禁有載插拔 MC4、水上/邊坡防護、LOTO 掛牌上鎖）。

## 🧭 標準作業流程 (Standard Workflow)

```
 [步驟 1: 資料盤點] ──> [步驟 2: 8D 根因分析] ──> [步驟 3: 財務量化評估]
        │                       │                        │
        v                       v                        v
 [圖紙/SCADA/照片]      [四維審計/排除假設]        [抑草蓆 vs 割草 ROI]
        │                       │                        │
        └───────────────────────┴────────────────────────┘
                                │
                                v
               [步驟 4: 產出 8D Markdown 報告]
                                │
                                v
             [步驟 5: 填寫 plant_spec.json 配置檔]
                                │
                                v
       [步驟 6: 執行 generate_solar_platform.py 編譯]
                                │
                                v
           [步驟 7: 發佈至 GitHub Pages & 雲端硬碟同步]
```

### 步驟 1：輸入資料盤點
蒐集案場相關資料：
* **工程圖紙**：竣工模組串接圖（如 C-002），逐台核算真實組件片數與真實 kWp。
* **SCADA 匯流排數據**：逐日發電度數 (kWh)、等價發電時數 (Ey)、日射量 ($W/m^2$)、模組溫度、逆變器告警狀態。
* **現場照片與標註圖**：雜草生長覆蓋實拍、割草後草屑未清運特寫、紅框重災分佈標註。
* **微氣候與地理資訊**：地號、經緯度坐標、臨海距離、地下水位與風力條件。

### 步驟 2：執行 8D 異常診斷 (D0 ~ D8)
1. **D0/D3 緊急反應**：判定是否需停機；檢視乾草火載量與直流電弧風險；啟動 LOTO。
2. **D2 量化描述**：計算平台建檔容量誤差；以真實容量重算 90 天單位發電量排名與累計短少度數。
3. **D4 根本原因**：
   - 梳理比值變化趨勢（如 0.541 $\rightarrow$ 0.510 $\rightarrow$ 停機 5 天 $\rightarrow$ 復機後惡化至 0.446）。
   - 列出排除之假設（逆變器削峰、電氣斷路、分組偏低、PID/衰退）。
   - 揭露延伸風險（旁路二極體過熱、熱斑與模組報廢）。
4. **D5 永久對策**：比選改除草 SOP（主方案）、防草蓆工法（評估中）等方案。
5. **D6 驗證門檻**：設定比值恢復 $\ge 0.90$ 為有效門檻；低於 $0.80$ 啟動 IEC 62446-1 電氣檢測。
6. **D7 防再發**：草屑清運寫入驗收、生長季每月割草、平台中位數落後 15% 自動告警。

### 步驟 3：撰寫 8D Markdown 報告
參考 [`resources/8d_report_template.md`](./resources/8d_report_template.md)，填寫完成工程歸檔報告。

### 步驟 4：自動編譯標準化 HTML 決策平台
1. 參照 [`examples/daan_guike_sample_spec.json`](./examples/daan_guike_sample_spec.json) 建立案場配置檔 `plant_spec.json`。
2. 執行自動生成腳本：
   ```bash
   # 生成標準版（內建雙模式切換、ECharts、Leaflet、照片燈箱與 CSV 匯出）
   python scripts/generate_solar_platform.py \
     --spec plant_spec.json \
     --daily-data daily_data.json \
     --output index.html
   ```

### 步驟 5：發佈與同步
1. **GitHub Pages 發佈**：推播至儲存庫 `main` 分支。
2. **Google Drive 同步**：同步複製至業主與維運工作資料夾。
